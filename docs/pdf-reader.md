# PDF reader and annotations

Vault PDFs open in Reader by default, including PDFs opened from the file explorer, links, and restored PDF tabs. The plugin routes PDF file tabs using public workspace events; it does not modify Obsidian's built-in PDF renderer or extension registry. To use the built-in viewer, run **Reader Plugin: Open PDF in Obsidian's normal viewer**. That tab stays in the normal viewer for the chosen document. A new ordinary PDF tab still opens in Reader. The fallback choice lasts for the current plugin session. PDF embeds inside Markdown retain Obsidian's embedded rendering.

The Reader shows every page in one continuous scroll using bundled PDF.js 6.4.299 and its matching worker. Only pages within about one screen of the view have a canvas and text layer; pages farther away are released, so long books stay responsive. Pages use the first page's size until they load. A floating bar at the bottom center holds previous/next page arrows, the page number field, zoom out/in, the zoom percentage, and a reset button. Previous returns to the top of a partly scrolled page before moving up a page. The percentage opens Fit width, Fit page, and preset zooms. Reset returns to Fit width, which is the default and follows pane and sidebar resizing. 100% matches the printed page size. Ctrl/Cmd-wheel zooms around the pointer; existing canvases stretch while zoom changes and are re-rendered sharply once it settles. Each tab stores its page, position within the page, and zoom in Obsidian's workspace state. The plugin also remembers where each PDF was last read, by vault path, in its data file: opening a PDF in a new tab, or after closing it or restarting Obsidian, continues at that spot and zoom. Links that name a page still open at that page. Renaming the PDF keeps its position; the 200 most recently read PDFs are remembered. A background tab applies a restored position when it first becomes visible. **Zoom in**, **Zoom out**, **Reset zoom**, and **Show table of contents** are also commands that can be assigned hotkeys.

The view header has a table of contents button for PDFs with an outline. It opens a collapsible tree of chapters and sections with page numbers. The dialog is centered in the window and is as tall as its rows, up to 80% of the window; beyond that the list scrolls. Only chapters show at first, except that the chapter containing the current page is opened down to the section being read, which is selected and marked in the accent color. Click a chevron to open or close a section; click a title to jump to the heading's position. The search field filters titles and shows each match under its chapters and sections, which are dimmed. Arrow keys move the selection, Page Up/Down move ten rows, Right opens a section or moves to its first child, Left closes it or moves to its parent, and Enter jumps. The tab's **⋯** menu includes **Open in Obsidian's PDF viewer**. When none of the first twelve pages has selectable text, a hint explains that the PDF needs OCR.

Select text to show a popup at the cursor. A color swatch creates a highlight in that color, and hovering or focusing a swatch previews that color on the selection. Number keys 1–9 pick the matching swatch. No swatch is marked in this popup, since nothing is highlighted yet. The labeled **Comment** button creates a highlight in the last used color and opens a comment field. The popup shows no hover tooltips. Obsidian shows a tooltip for any element with an `aria-label`, so the popup, the table of contents, and comment fields name things for screen readers with hidden text or placeholders instead. Selections that cross a page break create one highlight per page. Keyboard selections show the same popup at the end of the selection. Click an existing highlight to open its popup: swatches change the color, the comment button adds or removes the comment, and the other buttons copy the passage or delete the highlight. Deleting shows an Obsidian notice with **Undo**. Copying and other short confirmations appear just above the page and zoom bar instead of in Obsidian's notice corner. Hovering a highlight darkens it, and a small dot marks highlights with comments. Popups sit next to the passage, scroll with it, and close with Escape or a click elsewhere. Dismissing a selection popup also clears the selection, and that click does nothing else, even on a highlight. Comment fields grow with their text up to a limit and then scroll; they cannot be resized. Enter finishes a comment and Shift+Enter starts a new line. Changes save as you type. The highlight commands act on the current selection.

Annotations live in Obsidian's native right sidebar. The panel follows the active Reader document and keeps that context while you edit in the sidebar. **Toggle PDF annotations** in the command palette, or the highlighter button in the Reader header, opens it, or closes it when it is showing: a sidebar panel collapses its sidebar, and a panel moved into the main area closes. After you close it, switching PDFs does not reopen it until you toggle it again. Passages appear in page and text order, grouped under page headings, as full-width cards with a strip in the highlight's color. Click a card, or focus it and press Enter, to scroll to the passage and briefly pulse it. Click a comment to edit it in place; Enter finishes and Shift+Enter starts a new line. Hovering a card shows buttons to recolor it, add a comment, and delete it with Undo.

Each PDF has a **book note**, an ordinary Markdown note in the book notes folder (`Book notes/` by default) named after the PDF. It is created with the first highlight, and it holds a quote section for every highlight in reading order: a `[!quote]` callout with the page, an **Open passage** link that scrolls the Reader to the highlight and pulses it, a `[[book.pdf#page=N|PDF]]` link that works without the plugin, and a block ID, so other notes can link to or embed the passage. Write under a quote as much as you like. The note belongs to you: the plugin only adds sections for new highlights, before the first section from later in the book or at the end, and when a highlight is deleted it removes that section only if nothing is written under it and its quote is unedited. Headings, other text, and moved sections are left alone. The note's header comes from a template note when one is set (`{{title}}`, `{{source}}` and `{{date}}` are filled in, and a `source` property is added), or is a `source` link and a `book-note` tag. The pencil button in the Reader header and **Open book note** open it beside the PDF or in a new tab, as set in settings. If the note is deleted, the next change creates a new one. The record stores the note's path, so renaming or moving either file keeps them paired. Clicking a link to a PDF in a note opens it in the Reader at the linked page, reusing a Reader that already shows it, and leaves the note open.

Plugin settings define the highlight palette. Primary (yellow, ID `yellow`) and Secondary (blue, ID `blue`) always come first, in that order: you can rename and recolor them, but not move or remove them, and their rows show a lock instead of a grip. Loading settings restores them at the top if a data file lacks them or lists them elsewhere, keeping their saved names and colors. Colors you add follow them; you can rename, recolor, and remove them, and reorder them among themselves by dragging the grip at the start of each row or with the up and down arrow buttons. The whole strip left of the swatch grabs the row; Escape cancels a drag, and a focused grip also moves with the up and down arrow keys. Arrow buttons that cannot move a color are dimmed. When another Obsidian on the same vault, or Obsidian Sync, changes the plugin's data file, open windows adopt the new settings and reading positions instead of overwriting them later; a position read in this window but not yet saved is kept. New installs start with just these two. Settings saved by version 0.1, which stored only names for four fixed colors, load as those four colors, with yellow and blue first. Names appear in the sidebar and Markdown exports. Highlights store a color ID, so renaming or recoloring updates existing highlights. Highlights whose color was removed appear gray until they are given another color. Settings also choose the annotation folder. Changing it moves existing record and export pairs with Obsidian's file manager, so links to the Markdown exports follow them; other files in the old folder stay, and the old folder is removed only when it is empty.

All edits update open Reader views and the sidebar immediately and save automatically. There is no save indicator. Changes made during a write queue another save, and both files use the same snapshot. The store skips superseded queued writes. If the vault cannot be written, a notice reports the problem once, the sidebar shows that saving is retrying, and the plugin retries every two seconds. Another notice confirms when saving recovers. Pending edits remain in memory while Obsidian is running.

## Storage format

The annotation folder, `Reader annotations/` by default, contains `<document-id>.json` and `<document-id>.md`. JSON is authoritative. The Markdown file is regenerated in full, so freeform writing belongs in separate user notes. Each exported quote has a stable block ID for Obsidian links, plus a link that opens the source PDF's page through the Reader protocol handler. Open protocol links while this vault is active.

JSON schema version 1 contains:

- `documentId`: generated UUID, independent of the source filename.
- `sourcePath`: last-known vault-relative path.
- `fingerprint`: SHA-256 of the complete source PDF.
- `annotations`: passage records with UUID, one-based `page`, `color` (a palette ID from settings, such as `yellow` or `color-mv782u06`), `comment`, and ISO `createdAt`.
- Each passage has a `quote` selector with `exact`, `prefix`, and `suffix`; a page-local `position` selector with zero-based `start` and exclusive `end`; and `rects` with normalized `x`, `y`, `width`, and `height` relative to the rendered page. Text offsets count JavaScript UTF-16 units in the text layer's text content, excluding layout-only line breaks. `quote.exact` keeps those line breaks as newline characters so words on adjacent lines stay separate; it is therefore not always `end - start` characters long. Each rectangle covers one selected line. Rectangles scale with zoom.

Vault file and folder rename events update source paths and exports. A byte-identical PDF moved outside Obsidian reconnects by fingerprint when its previous path no longer exists. Identical copies at existing paths receive separate document IDs. Replacing an annotated PDF with different bytes at the same path is rejected to avoid applying old locations to a changed edition. Restore the original or place the new edition at a different vault path. Invalid or unsupported records are preserved and reported instead of overwritten.

The store shares one in-memory record between Reader tabs, broadcasts edits and save status to subscribers, and serializes writes. External edits to an open JSON record are not merged into that cached record. Close and reload the plugin before externally editing records. JSON and Markdown are two separate writes; the JSON can be newer than the export after a partial write failure.

## Development verification

`pnpm build` deploys the plugin and creates `Books/Sample reading book.pdf` in this checkout's disposable vault. It is an original two-page fixture generated by `scripts/sample-pdf.mjs`. Run `pnpm test` for storage, identity, validation, and save-failure checks. Run both before merging.

Register this checkout's `.dev-vault/Reader Plugin Dev - <checkout-directory>/` with Obsidian. Enable community plugins in that development vault, reload Reader Plugin, and open the sample PDF through the Reader command. Verify default PDF opening, the normal-viewer fallback, continuous scrolling and the page field, previous/next, zoom buttons, presets, reset, Ctrl/Cmd-wheel zoom, the table of contents, selection popup positioning, highlighting with each color, highlight and comment, clicking a highlight to recolor, comment, copy, and delete with Undo, sidebar jumping and comment edits, settings changes to colors and the annotation folder, and reopening at the saved position. Open two Reader tabs for the same PDF and check that a comment edit updates both records before the field loses focus. Simulate a write failure and confirm the notice appears and automatic retry recovers without a manual action. Confirm the JSON and Markdown files contain the saved quote and comment.

For a long real book, copy a personal PDF into `Books/` in the checkout's development vault. The vault is ignored by Git; do not add personal books to `scripts/dev-vault.mjs`. This pass was exercised with a 1,108-page text book.

This phase covers text PDFs and was exercised in Obsidian 1.14.4 on Linux. Pages without selectable text show an OCR message. OCR, EPUB, assistant integration, and retrieval remain future work. The 500-page startup and indexing targets in the workflow plan have not been benchmarked by this implementation.
