# PDF reader and annotations

Vault PDFs open in Reader by default, including PDFs opened from the file explorer, links, and restored PDF tabs. The plugin routes PDF file tabs using public workspace events; it does not modify Obsidian's built-in PDF renderer or extension registry. To use the built-in viewer, run **Reader Plugin: Open PDF in Obsidian's normal viewer**. That tab stays in the normal viewer for the chosen document. A new ordinary PDF tab still opens in Reader. The fallback choice lasts for the current plugin session. PDF embeds inside Markdown retain Obsidian's embedded rendering.

The Reader renders one page at a time with bundled PDF.js 6.4.299 and its matching worker. Page controls and zoom work without loading canvases for the whole document. **Fit width** adapts to pane and sidebar resizing. Percentage choices use the actual PDF scale, with plus/minus controls and Ctrl/Cmd-wheel for adjustments. Zoom preserves the vertical reading position. Reader page and zoom are stored with the tab's Obsidian workspace state.

Select text on the current page to show a popup beside the cursor. Choose a color and use **Highlight** or **Comment**. Comment creates a highlight and opens an editor in the popup. Changes save as you type; **Done**, Escape, or clicking outside closes the popup. The popup stays within the window bounds. Both highlight actions also have commands that can be assigned hotkeys. Category names can be changed in plugin settings.

Annotations live in Obsidian's native right sidebar. The panel follows the active Reader document and keeps that context while you edit in the sidebar. **Show PDF annotations** in the command palette, or **Annotations** in the Reader toolbar, reveals it. Passages appear in page and text order. Their page buttons return to the marked position. Comments are editable in the sidebar. **Delete highlight** removes a passage and **Undo deletion** restores the latest deleted highlight for its document during the sidebar session.

All edits update open Reader views and the sidebar immediately and save automatically. **Saving…** indicates pending writes; **Saved** means both JSON and Markdown have been written for the latest edit. Changes made during a write queue another save, and both files use the same snapshot. The store skips superseded queued writes. If the vault cannot be written, **Retrying save…** shows the problem and the plugin retries every two seconds. The status tooltip contains the write error. Pending edits remain in memory while Obsidian is running. No manual save action is required.

## Storage format

The vault folder `Reader annotations/` contains `<document-id>.json` and `<document-id>.md`. JSON is authoritative. The Markdown file is regenerated in full, so freeform writing belongs in separate user notes. Each exported quote has a stable block ID for Obsidian links, plus a link that opens the source PDF's page through the Reader protocol handler. Open protocol links while this vault is active.

JSON schema version 1 contains:

- `documentId`: generated UUID, independent of the source filename.
- `sourcePath`: last-known vault-relative path.
- `fingerprint`: SHA-256 of the complete source PDF.
- `annotations`: passage records with UUID, one-based `page`, `color`, `comment`, and ISO `createdAt`.
- Each passage has a `quote` selector with `exact`, `prefix`, and `suffix`; a page-local `position` selector with zero-based `start` and exclusive `end`; and `rects` with normalized `x`, `y`, `width`, and `height` relative to the rendered page. Text offsets count JavaScript UTF-16 units in the text layer's text content, excluding layout-only line breaks. Rectangles scale with zoom.

Vault file and folder rename events update source paths and exports. A byte-identical PDF moved outside Obsidian reconnects by fingerprint when its previous path no longer exists. Identical copies at existing paths receive separate document IDs. Replacing an annotated PDF with different bytes at the same path is rejected to avoid applying old locations to a changed edition. Restore the original or place the new edition at a different vault path. Invalid or unsupported records are preserved and reported instead of overwritten.

The store shares one in-memory record between Reader tabs, broadcasts edits and save status to subscribers, and serializes writes. External edits to an open JSON record are not merged into that cached record. Close and reload the plugin before externally editing records. JSON and Markdown are two separate writes; the JSON can be newer than the export after a partial write failure.

## Development verification

`pnpm build` deploys the plugin and creates `Books/Sample reading book.pdf` in this checkout's disposable vault. It is an original two-page fixture generated by `scripts/sample-pdf.mjs`. Run `pnpm test` for storage, identity, validation, and save-failure checks. Worktrunk's merge hook runs both commands.

Register this checkout's `.dev-vault/Reader Plugin Dev - <checkout-directory>/` with Obsidian. Enable community plugins in that development vault, reload Reader Plugin, and open the sample PDF through the Reader command. Verify default PDF opening, the normal-viewer fallback, selection popup positioning, both highlight actions, category selection, popup and sidebar comment edits, page navigation, zoom, sidebar context, delete/undo, and reopening. Open two Reader tabs for the same PDF and check that a comment edit updates both records before the field loses focus. Simulate a write failure and confirm automatic retry restores Saved without a manual action. Confirm the JSON and Markdown files contain the saved quote and comment.

This phase covers text PDFs and was exercised in Obsidian 1.14.4 on Linux. Pages without selectable text show an OCR message. OCR, EPUB, assistant integration, and retrieval remain future work. The 500-page startup and indexing targets in the workflow plan have not been benchmarked by this implementation.
