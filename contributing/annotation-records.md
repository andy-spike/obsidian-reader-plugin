# Annotation records

This page describes the JSON files Reading Desk writes for each PDF. Readers who only want to know where their data lives should see [Files, sync, and renaming](../docs/files-and-sync.md).

The annotation folder, the hidden `.reader-annotations/` by default, holds one `<document-id>.json` record per PDF. The record is the authority for highlights. Everything the reader writes lives in Markdown: comments in quote notes, which carry the highlight ID in their `annotation` property, and other writing in the book note, whose quote sections carry the block IDs and passage links (`obsidian://reader-plugin?document=…&annotation=…&page=…`). The Reader's protocol handler opens those links while the vault is active.

The plugin reads and writes these files directly, because Obsidian does not index hidden folders.

## Schema version 1

- `documentId` is a generated UUID, independent of the source filename.
- `sourcePath` is the last-known vault-relative path.
- `fingerprint` is the SHA-256 of the complete source PDF.
- `notePath` is the book note's vault path, once the note exists. `exportRetired` is set once the Markdown file generated by older versions has been handled.
- `annotations` holds the passage records. Each has a UUID, a one-based `page`, a `color` (a palette ID from settings, such as `yellow` or `color-mv782u06`), an empty `comment` (comments from older versions move to the book note), and an ISO `createdAt`.
- Each passage has a `quote` selector with `exact`, `prefix`, and `suffix`. It also has a page-local `position` selector with zero-based `start` and exclusive `end`, and `rects` with normalized `x`, `y`, `width`, and `height` relative to the rendered page.

Text offsets count JavaScript UTF-16 units in the text layer's text content, excluding layout-only line breaks. `quote.exact` keeps those line breaks as newline characters so words on adjacent lines stay separate, so it is not always `end - start` characters long. Each rectangle covers one selected line, and rectangles scale with zoom.

## Identity and renames

Vault rename events update the source and book note paths. A byte-identical PDF moved outside Obsidian reconnects by fingerprint when its previous path no longer exists. Identical copies at existing paths get separate document IDs. Replacing an annotated PDF with different bytes at the same path is rejected, so old locations never apply to a changed edition. Invalid or unsupported records are preserved and reported, never overwritten.

## Store behavior

The store shares one in-memory record between Reader tabs, broadcasts edits and save status to subscribers, and serializes writes. It skips superseded queued writes. External edits to an open JSON record are not merged into the cached record, so close and reload the plugin before editing records by hand.

## Legacy migrations

Versions before book notes kept comments in the record and regenerated a `<document-id>.md` file beside it. The first time each PDF syncs after updating, its comments are added under their quotes in the book note. Each comment is cleared from the record only after the note on disk is read back and holds it. The old Markdown file then goes to the trash, following Obsidian's trash setting, unless another note links to it. Passage links (`document=…`) don't count as links to it.

Versions before the hidden folder kept records in the visible `Reader annotations/`. If the setting still names that folder, the plugin moves the records to the hidden one once and removes the old folder when it is empty.
